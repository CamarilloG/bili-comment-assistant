### 1. 控制台运行日志不显示 — 修复

**现象**  
Web 控制台「运行日志」区域一直显示「等待日志输出...」，养号/评论任务有日志但页面无输出。

**根因**  
- 当存在 `app/web/frontend` 目录时，后端将旧版前端挂载在 **`/`**（`app.mount("/", StaticFiles(...))`），会拦截所有路径（包括 `/ws/logs`）。  
- WebSocket 连接 `/ws/logs` 被当作静态文件请求处理，无法到达 `log_api`，导致后端 `broadcast_log` 时订阅者始终为 0，日志发不出去。

**修复**  
- 将旧版前端静态挂载由 **`/`** 改为 **`/app`**（`app.mount("/app", StaticFiles(...))`），使 `/ws`、`/api` 不再被静态路由拦截，运行日志 WebSocket 正常连通。  
- 控制台运行日志按槽位订阅（`/ws/logs?slot=<id>`），Dashboard 使用 `displayLogs = computed(() => taskStore.logsBySlot[slotStore.currentSlot])` 直接展示当前实例日志，避免引用不同步导致不更新。

**涉及文件**  
- `app/web/app.py`：`frontend_dir` 挂载路径由 `"/"` 改为 `"/app"`  
- `app/web/frontend-v2/src/views/Dashboard.vue`：运行日志区域绑定 `displayLogs`（当前槽位日志数组）

### 2. 养号验证码逻辑 — 改为原地等待用户解决

**原逻辑**  
养号流程（首页进入、进入观看页、观看过程中）一旦检测到验证码即**直接退出**养号任务。

**新逻辑**  
- 检测到验证码后**不再退出**，而是：  
  - 停止后续自动化操作（不点击、不翻页）；  
  - 打一条警告日志并触发风控提醒（`notify_captcha_alert`）；  
  - **每 5 秒轮询**页面，直到验证码消失或用户点击「停止」；  
  - 验证码消失后打「验证码已解决，继续养号/观看...」并继续任务。  
- 若在等待期间用户点击停止，则按原逻辑退出。

**涉及文件**  
- `app/core/warmup.py`：新增 `_wait_captcha_resolved()`；首页/进入观看页/观看中三处「检测到验证码则退出」改为调用该方法等待用户解决后继续。

### 3. 多槽位与按实例运行日志（此前已实现，本次仅修复展示）

- 后端：`log_api` 按 slot 维护订阅队列，`broadcast_log` 使用 `slot_id_ctx` 投递到对应槽位；`/ws/logs` 通过 query `slot` 只推送该槽位日志。  
- 前端：`taskStore.logsBySlot` 按槽位存日志，`connectLogs(slot)` 连接对应 slot 的 WebSocket，Dashboard 展示当前实例的 `displayLogs`。  
- 架构文档中多槽位与运行日志相关描述见「项目架构与实现说明」4.4、4.8 及 5。

### 4. 手动添加实例（突破固定 3 个限制）

- **槽位列表**：`list_slot_ids()` 改为动态发现——返回 `["0"]` + 扫描 `app/instances/` 下纯数字目录名并排序，不再固定 3 个。
- **添加实例**：新增 `add_slot()`（`core/slot.py`）创建下一编号目录并写入默认 config/cookies；新增 `POST /api/instances` 调用 `add_slot()` 并返回 `{ id, slots }`。
- **前端**：`instancesApi.add()`、slotStore 新增 `addInstance()`；控制台顶部实例下拉旁增加「+ 新建实例」按钮，成功后刷新列表并切换到新实例；`logsBySlot` 初始改为 `ref({})`，新实例在 `connectLogs` 时按需初始化。

### 5. 智能评论/智能筛选开关仅影响 AI 模式

- **原问题**：配置中开启「启用智能评论」或「启用智能筛选」但未填 api_key 时，`ConfigValidator._validate_required_fields` 在加载配置时直接报错，导致即使用户只跑普通模板评论也会失败。
- **修复**：移除配置层对「智能评论/智能筛选已开启则必须填 api_key/base_url」的校验。运行时 AIManager 在无 api_key 时不创建 provider，`is_comment_enabled()`/`is_filter_enabled()` 为 False，普通模板评论正常执行；仅在选择 AI 评论模式且已配置 api_key 时才会启用智能评论/智能筛选。
